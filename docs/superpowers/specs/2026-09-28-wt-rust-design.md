# wt in Rust: design

Status: design approved 2026-09-28.

## 1. Purpose

`wt` turns an intent into a git worktree: a sibling directory, nested by branch name, with
gitignored files seeded, setup commands run, and the tracker told. Today it is
`~/.config/wt/wt.py` (Python, run through `uv`). This repo replaces it with a Rust binary that
is a **drop-in**: same config files, same sidecars, same stdout protocol, same verbs. Existing
worktrees made by the Python tool keep working after the switch.

Released as GitHub Releases only (cargo-dist + release-plz, `git_only`), never crates.io.

`docs/feature-inventory.md` is the behaviour reference. Unless this spec says otherwise, the
Rust port does what the inventory describes, with the same messages. Where this spec and the
inventory disagree, this spec wins.

### Non-goals

- No interactive pickers, no prompts. Every child process gets a null stdin.
- No GitHub Enterprise or GitLab provider (inventory #27). Provider `none` still works for
  `new`, `branch`, `ls`, `cd`, `rm`, and hooks.
- No bash wrapper. `pwsh` and `zsh` only.
- No crates.io publish.

## 3. Architecture: facts in, plan out

Pure core, thin IO shell. The shell gathers facts, a pure function decides, the shell executes.

```
src/
  main.rs           clap, logging init, run(); anyhow only here
  error.rs          AppError (thiserror)
  domain/           pure: facts in, plan out
    paths.rs        WT_HOME / home -> config dir, log dir
    config.rs       DEFAULTS layer, parse, validate, deep-merge, resolve
    parse.rs        worktree porcelain, for-each-ref, reflog, remote URL
    naming.rs       slugify, fill, BRANCH_SPEC, model reply, name precedence
    select.rs       leaf, find_targets, select_one
    plan.rs         Step, plan_create, plan_remove, stale/merged decisions
    provider.rs     az / gh argv builders, JSON reply -> Outcome
    herdr.rs        herdr argv builders, reply parsers, labels, release_panes decision
    view.rs         ls table, complete list, dry-run text, init scripts
  io/               IO
    git.rs          spawn git: utf-8, null stdin, timeout
    cli.rs          spawn az / gh / herdr / claude / exec steps
    run.rs          gather facts, execute steps, roll back
```

Module boundaries may shift during implementation. The pure/IO split does not.

### Phased planning

Some decisions need an earlier IO result (`pr` must look up the head sha before it can plan the
`worktree add`). So each verb runs in phases: gather facts, plan purely, execute, map the replies
purely into outcomes, repeat. Each plan is plain data:

```rust
enum Step {
    Fetch { remote: String, refspec: Option<String> },
    AddWorktree { path: PathBuf, arm: AddArm },       // detach / existing / guess-remote / new -b
    Seed { copy: Vec<RelPath>, symlink: Vec<RelPath> },
    WriteSidecar { file: PathBuf, meta: Meta },
    Exec { cmd: String, shell: Vec<String>, timeout: Duration },
    // ... push, tracker writes, herdr open, pane runs, remove, delete branch, prune
}
```

`run.rs` records which reversible steps completed (worktree added, branch created, sidecar
written, files seeded) and undoes exactly those on failure. No traits, no fakes: tests assert on
plans and on pure reply parsing.

### Facts

A `Facts` value holds what a plan needs: main root, common dir, worktree list, sidecars, merged
config, provider, remote, default branch, and `now`. Gathering it is IO; everything downstream
takes `&Facts`.

## 4. Behaviour

### Verbs

`new`, `item`, `pr`, `branch`, `ls`, `cd`, `open`, `rm`, `complete`, `hook-create`,
`hook-remove`, plus the new `init`. Flags as in inventory §1. `-q/--quiet` is global and
accepted anywhere on the line.

### Paths

- Config: `~/.config/wt/config.toml` on every OS, then `<main-root>/.wt.toml`.
- Log: `~/.local/state/wt/wt.log`, via `tracing-appender`. Never stdout.
- `WT_HOME`, when set, puts both under one directory (`$WT_HOME/config.toml`,
  `$WT_HOME/wt.log`). Tests and dev runs set it.
- Sidecars: `<git-common-dir>/wt/<percent-encoded leaf>.json`, byte-compatible with the Python
  tool (same keys, `indent=2`, `created` as UTC ISO 8601). New keys may be added; existing keys
  keep their meaning.

### stdout protocol

stdout carries only: the worktree path (create verbs, `cd`, `hook-create`), the `ls` table, the
`complete` names, and the `init` script. Everything else goes to stderr.

**Changed:** when a tree exists but a later step failed (push, link, state, exec, `--open`), the
path is still printed, the exit code is 1, and the wrapper still cds. This holds for every verb,
so a failed `--open` is a failure everywhere (inventory #18, #19).

**Exception:** `hook-create` exits 0 when a non-strict exec step failed. It prints the path and
warns on stderr: a failing `WorktreeCreate` hook would make Claude Code drop a tree that exists.

### Exit codes

0 success, 1 `wt: {msg}` on stderr, 2 usage error from clap. No panics, no tracebacks: every
failure the Python tool let through as a traceback (inventory #20 to #23) becomes a `wt:` error.

### Shell integration: `wt init pwsh|zsh`

The binary prints the wrapper, zoxide style:

- pwsh: `Invoke-Expression (& wt init pwsh | Out-String)` in `$PROFILE`
- zsh: `eval "$(wt init zsh)"`

The wrapper:

- calls the binary by the absolute path `init` was run from (`current_exe`), never through
  `PATH`, so Windows Terminal's `wt` alias cannot win
- captures stdout only, re-emits it, and cds when the last line is an existing directory;
  with `--open` it cds to the main checkout instead
- before `rm`, steps out to the main checkout (Windows cannot remove a process's cwd)
- registers completion from `clap_complete`'s dynamic engine. Worktree names for `rm`, `cd`,
  `open` come from the same code as `wt complete`. No cache: the Rust binary starts fast.
- hides `complete`, `hook-create`, `hook-remove`, `init` from completion

### ADO

All ADO HTTP goes through `az rest --resource 499b84ac-1321-427f-aa17-267ca6975798` (without
it the call silently no-ops and exits 0). Norwegian text must not cross az's argv or be read back
from a pipe:

- Work item lookup: `az rest --method get --url .../_apis/wit/workitems/{id}?fields=System.Title,System.WorkItemType&api-version=7.1 --output-file <tmp>`, then read the file as UTF-8.
- Link branch and set state: two separate `az rest --method patch`, body from a UTF-8 file,
  `Content-Type=application/json-patch+json`.
- Retry: 3 attempts with jittered backoff, only on transient failures (transport errors,
  `Too Many Requests`, 5xx). The classifier over az's stderr is pure and tested.
- `RelationAlreadyExists` in the reply means "already linked", not a failure.
- `az repos pr show` stays as in the Python tool. `az repos show` is gone: the repo and
  project ids for the link come from an `az rest` GET of `_apis/git/repositories/{repo}`, read
  back from a UTF-8 file like the work item lookup.

GitHub uses `gh` as in the Python tool.

## 5. Fixes over the Python tool

Kept formats, fixed behaviour. Each is one test that fails on the Python behaviour.

### Later decisions

Settled during implementation, each with a test:

- Prunable trees: `ls` shows `missing` when the directory is gone and `prunable` when only its
  `.git` link is broken. `cd` and `complete` skip both. `rm` cleans up a gone tree without
  `--force`; under `delete_branch = "always"` it first counts the branch's unpushed commits from
  the main checkout and refuses (like a dirty tree) when there are any or the count fails. A
  broken-link tree is refused outright, even with `--force`, and sweeps skip it. A create that
  hits a branch checked out in a prunable tree says which of the two fixes applies.
- A create whose target path exists but is not a registered worktree is refused, never reused.
- `ttl_days <= 0` is treated as unset, so the mode is never stale. `exec_timeout` and
  `[naming] timeout` must be positive. List options refuse non-string entries.
- `--run ""` counts as absent (Python's falsy check), so it is not refused without `--open`.
- The full provider parse (org/project/repo, with F2's check) runs only for `pr` and `item`;
  every other verb reads the host alone, so an odd remote never breaks `ls`, `new` or `rm`.
- `rm` judges a tree against `{remote}/{default branch}`, the default branch looked up once
  per run; a failed lookup falls back to the `default_branch` of the mode the tree was made in.
- The naming model runs with the config dir as cwd, so a repo's own `CLAUDE.md` cannot load
  into it. Its argv goes through std's batch-safe quoting, never a hand-built `cmd /c` line.
- An exec step is killed after `exec_timeout`; its output readers then get 2 s to drain, and a
  process it left holding the pipes is abandoned with a warning. git, az and gh calls get the
  same bounded drain.
- On Windows wt clears the inherit flag on its own std handles at startup, so a process an exec
  step leaves in the background cannot hold the caller's pipes open.
- F2's name check uses Unicode alphanumerics (Rust's `char::is_alphanumeric`), matching
  Python's `str.isalnum`.
- `--open` without herdr is a skip; when exec steps were deferred to the workspace, wt says how
  many did not run.
- The pwsh wrapper decodes wt's stdout as UTF-8 while it runs, so a non-ASCII path cds.
- A closed stdout is a quiet exit, not a panic. A log dir that cannot be made turns logging off
  with one warning instead of failing the call.

## 6. Testing

TDD. Red, green, refactor, per behaviour.

1. **Pure unit tests** in-module (`#[cfg(test)] mod tests`). Port every pure test class in
   `test_wt.py` (config precedence, deep merge, validation, slugify, branch spec, fill, provider
   parse, porcelain, find targets, already-linked, retry classifier, GitHub type map) plus one
   test per fix in §5.
2. **Plan tests** assert the `Step` sequence for each verb and each policy branch.
3. **Snapshots**: inline `insta` for the `ls` table, dry-run text, and `init` scripts. Never
   accept a snapshot you have not read.
4. **Integration tests** in `tests/`, real `git`, a bare origin in a tempdir, `WT_HOME` set,
   git isolated with `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM=1` and fixed author/committer env.
   They drive the built binary. Cover: the new/ls/rm round trip (exact stdout path, `.env`
   seeded), rollback on a failed seed and on `exec_strict`, exec output never on stdout, a
   hanging exec step bounded, the teardown policy (dirty refused, force, purge, main protected,
   sidecar survives a failed removal), `--stale`, `--merged` (including F1), hooks (two sessions,
   same session, malformed payload, exact path), and drop-in compatibility: a sidecar written by
   the Python tool is read and torn down.
5. `az`, `gh`, `herdr` and `claude` are never spawned in tests. Their argv and reply parsing are
   pure and tested with JSON strings.

Gate before any bead closes: `cargo fmt --check`, `cargo clippy --all-targets`,
`cargo nextest run`, all green.
